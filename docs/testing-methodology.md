# Testing methodology

The original full local and deployed evidence was executed on 12 October 2026. Source inspection established defects first; unit/service tests verified business rules; actual Chrome browser tests then found and retested UI defects. The initial failed browser report is retained alongside the later passing results and screenshots. On 27 October a further stress run exposed a cross-process persistence defect that a single B09 run had missed. The correction and current local retests are recorded separately so historical production evidence is not presented as proof of the changed runtime.

## Appropriate automation

Node's built-in runner checks deterministic calculations, date boundaries, validation, CSV escaping and persistence failures. In Node, IndexedDB is unavailable, so the service deliberately uses its `localStorage` fallback; storage and fetch are replaced with controlled test doubles to produce malformed JSON, quota failures and overlapping operations reproducibly. These tests are fast and isolate business rules, but they do not prove the browser's IndexedDB transaction behaviour or rendering.

Playwright drives installed Chrome through the real static server. It submits forms, reloads to check IndexedDB persistence, tests history and keyboard focus, downloads a real CSV, delays or fails JSON requests, and edits from two tabs. B09 deliberately disables Web Locks, performs 20 pairs of simultaneous writes, then checks the authoritative workspace from both original pages and a newly opened third page. axe-core checks all six views at 320, 375, 768, 1024 and 1440px, plus the property dialog. Screenshots are generated by the browser, not by image generation. Browser plugin was not available; the testing skill's regular Playwright path was used.

ESLint checks JavaScript; html-validate checks both static HTML documents; CSS Tree parses CSS and validates supported property/value grammar. The separate `validate:official` command submits the source to the W3C Nu HTML and Jigsaw CSS services. Jigsaw's remaining warnings are retained because they are static-analysis limitations around CSS custom properties; no warning is silently converted into a pass. Prettier checks formatting. A local link checker verifies document and asset targets, not external network availability. npm audit assesses development dependencies at the recorded time.

## Appropriate manual testing

Manual checks remain necessary for screen-reader speech, understandable copy, task efficiency, physical touch devices, browser zoom and OS high contrast. A scoped agent-operated [native Chrome 200%/400% zoom review](manual-accessibility-review.md) is complete; the deployed Edge suite provides separate cross-browser evidence. These records do not establish screen-reader speech, actual OS contrast/touch-device use, Firefox/Safari behaviour or independent learner usability feedback. Automated contrast and ARIA checks cannot guarantee WCAG conformance. Have a learner or peer follow the manual checklist and record their own observations in test-results-template.md; never mark unexecuted work as passed.

## Reproduce

```sh
npm ci
npm test
npm run lint
npm run validate:html
npm run validate:css
npm run validate:official
npm run format:check
npm run check:links
npm run test:browser
npm run build
```

Use Node 24+ and an installed Google Chrome; versions actually used are in test-results.md. Every browser test has an isolated browser context and fictional records. Test output lives in docs/evidence. No submitted data is sent to a backend. Tests against the deployed origin use separate browser contexts and reports. Set BASE_URL and use playwright.deployed.config.js as shown in deployed-test-results.md; it disables the local server and saves all screenshots/reports to evidence/deployed, preserving local evidence.

## Interpretation

A pass means that the assertion passed in the named environment and revision, not that every possible use case passed. The failed initial browser run exposed dialog Tab behaviour, low contrast and invalid ARIA. A later repeated B09 run exposed a storage race even though an earlier single run had passed. Expected failure scenarios intentionally log a caught load error; these are distinguished from uncaught `pageerror` events. The corrected 27 October revision passed all 14 local browser workflows and all five local preference-accessibility checks. The 12 October cloud run passed 14 browser tests plus 13 independent HTTP/hash checks; see [deployed results](deployed-test-results.md). A new deployed run is still required for the changed runtime.

## Extended scope

Edge used the full shared browser suite in its own evidence folder for the earlier deployed revision. Forced colours/reduced motion were emulated in Chrome and explicitly distinguished from OS/assistive-technology checks. Virtual time advanced the exact 15-second timeout in service tests without adding an artificial delay to the app. The expanded Node total is 24 tests. For the IndexedDB correction, B05/B08/B09 passed together and B09 passed 10 repeated runs with Web Locks disabled: 400 two-tab writes in 200 simultaneous pairs. Details and limits appear in [additional verification](additional-verification.md).
